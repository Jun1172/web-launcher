# 进程管理

launcher 负责应用的进程生命周期：启动 → 就绪探测 → 关闭 → 进程树清理。

## 启动

- 用 `subprocess.Popen` 拉起 `cmd`
- `.py` / `.pyw` 自动前缀 Python 解释器
- 跨平台 Popen 参数：
  - Windows：隐藏控制台（`CREATE_NO_WINDOW`）
  - POSIX：设新会话，便于后续 `killpg` 整体回收

## 端口就绪探测

若 `app.json` 声明了 `port`：

1. 启动后用 `socket.create_connection` 轮询该端口
2. 直到端口监听成功（默认 6s 超时）
3. 前端以 iframe 内嵌该端口地址

**无 `port` 的应用**启动后即视为就绪（适合后台进程 / 守护类应用）。

> 端口以 launcher 分配给该实例的实际端口为准：优先 `app.json` 的建议端口，冲突时自动分配随机可用端口，并通过 `LAUNCHER_APP_PORT` 环境变量注入给应用。所以应用应读取该环境变量，而不是写死自己的端口。

## 优雅停止

`/api/close?id=<aid>` 触发：

1. `p.terminate()`（发 `SIGTERM`）
2. 等 2 秒
3. 兜底：Windows `taskkill /F /T /PID`，POSIX `os.killpg`，强杀整棵进程树

launcher 退出时 `atexit` 钩子会按同样流程顺序停掉所有子进程，避免 C/C++ 子进程变成孤儿。

## 进程隔离

- 每个应用是独立进程，**互不交互**（当前无 IPC 总线）
- 单个应用崩溃 / 退出不影响 launcher 或其他应用
- 应用之间通过 HTTP + 端口区分，由顶层页面统一调度
