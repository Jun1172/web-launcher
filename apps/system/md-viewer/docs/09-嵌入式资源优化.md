# 嵌入式主机资源优化指南

> 面向在 RK3588 / 树莓派 / Jetson / 工控机等嵌入式主板上部署 Web Launcher 的资源优化策略。
>
> 阅读前提：已按 [07-自更新与部署](07-自更新与部署.md) 完成 launcher 基础部署。

---

## 1. 资源消耗现状（实测数据）

以下数据在 Windows 11 + 1280×800 分辨率下实测，供参照：

| 组成部分 | 内存占用 | 占比 | 说明 |
| --- | --- | --- | --- |
| **WebView2 渲染引擎** | ~293 MB | 78% | Edge Chromium 内核，前端页面/动效/iframe 都在它里面跑 |
| **Python 解释器常驻** | 25-30 MB | 7% | launcher.py + 标准库 + pywebview |
| **launcher 业务逻辑** | < 5 MB | 1% | 应用扫描/进程管理/HTTP 路由，本身极轻 |
| **每个打开的 Python 子应用** | +20-30 MB | — | 每启动一个 app.py 就多一个 Python 进程 |

**关键结论**：99% 的资源消耗在 WebView2 和子应用进程，launcher 自身业务逻辑可忽略。优化重心应放在前端瘦身和子应用管控，而非重写 launcher。

---

## 2. 优化策略总览

按"改 config 即生效 → 改启动参数 → 改应用 → 改架构"四个层级，由易到难：

| 层级 | 策略 | 内存收益 | 难度 | 是否需重启 |
| --- | --- | --- | --- | --- |
| L1 | config.json 关动效 | 30-50 MB | 改文件 | 刷新页面 |
| L1 | 降低屏幕分辨率 | 40-80 MB | 系统设置 | 重启 launcher |
| L1 | 只装必需应用 | 2-5 MB | 布局编辑 | 刷新页面 |
| L2 | WebView2 低内存参数 | 40-80 MB | 启动参数 | 重启 launcher |
| L2 | 子应用改静态 HTML | 每个省 20-30 MB | 改造应用 | — |
| L3 | 纯 HTTP 模式（无窗口） | 省 pywebview 10 MB | 环境变量 | 重启 |
| L3 | 远程浏览器访问 | 省 WebView2 全部 | 网络部署 | — |

## 3. L1：config.json 即时生效（推荐首选）

### 3.1 关闭动态效果

`config.json` 顶部新增 `ui` 节（如已存在则修改）：

```json
{
  "ui": {
    "show_window_buttons": false,
    "fx_enabled": true,
    "fx_particle_count": 12,
    "fx_pointer_glow": false,
    "fx_meteor": false,
    "fx_ripple": true
  }
}
```

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `show_window_buttons` | bool | `true` | `false` 隐藏右上角 —▢✕ 按钮组（kiosk / 嵌入式全屏场景） |
| `fx_enabled` | bool | `true` | **总开关**。`false` 时下面 4 项全部失效，所有动效一个不留 |
| `fx_particle_count` | int | `38` | 背景星尘粒子数量。嵌入式建议 `12`-`20`；`0` 只关粒子，其余动效保留 |
| `fx_pointer_glow` | bool | `true` | 鼠标跟随光晕。关闭后不建 DOM、不挂监听、不跑 rAF，是单项里省得最多的一个 |
| `fx_meteor` | bool | `true` | 随机流星。关闭后不再有 `setTimeout` 定时唤醒 |
| `fx_ripple` | bool | `true` | 点击磁贴/图标时的扩散光环 |

**分级建议**：

| 场景 | 建议配置 |
| --- | --- |
| 桌面（追求观感） | 全部默认，`fx_particle_count: 38` |
| 嵌入式（有 GPU） | `fx_particle_count: 12`、`fx_pointer_glow: false`、`fx_meteor: false` |
| 嵌入式（软件渲染 / 最低功耗） | `fx_enabled: false` |

**生效方式**：保存 config.json 后，刷新页面即可（`/api/ui/config` 每次从磁盘读，无需重启 launcher）。

> ⚠️ **JSON 不支持注释**。虽然代码已加注释剥离容错（`_strip_json_comments`），但屏蔽配置请直接删除整行，不要依赖注释。

> ⚠️ **exe 读的是「exe 所在目录」的 config.json**，不是源码目录的。详见 [3.4 配置文件加载位置](#34-配置文件加载位置)。

### 3.2 降低屏幕分辨率

WebView2 的渲染缓冲区与分辨率成正比：

| 分辨率 | 渲染缓冲区估算 | 适用场景 |
| --- | --- | --- |
| 1920×1080 | ~24 MB | 桌面开发 |
| 1280×800 | ~10 MB | 当前默认 |
| 1024×600 | ~6 MB | 7-10 寸嵌入式屏 |
| 800×480 | ~3 MB | 小尺寸工控屏 |

**操作**：嵌入式主板显示配置里设为目标分辨率，launcher 窗口自动跟随。

### 3.3 精简应用列表

26 个应用的元数据常驻注册表（约 2 MB）。更重要的是——**dock 里的应用图标会预渲染**，隐藏不用的应用能减少 DOM 节点：

**操作**：桌面右上角 🗂️ → 布局编辑 → 勾选「隐藏」移除不常用的应用。嵌入式出厂建议只保留 5-8 个核心应用。

### 3.4 配置文件加载位置

这是「改了配置没生效」最常见的原因。

| 运行方式 | 实际读取的文件 |
| --- | --- |
| `python launcher.py` | `<源码目录>\config.json` |
| `launcher.exe` | **`<exe 所在目录>\config.json`** |

打包版把 `config.json` 打进了程序包（`--add-data "config.json;."`）。把 exe 单独拷到新目录首次运行时，会自动把包内那份释放到 exe 同目录；此后**只读同目录这份**，源码目录的改动不会影响 exe。

排查方法：看 `launcher.log` 开头两行，会打印实际生效的配置路径与版本号：

```
[INFO] 使用配置文件: C:\xxx\config.json
[INFO] 配置版本: 1.0.5
```

若路径不是你预期的那个文件，把正确的 config.json 复制到该目录即可。

## 4. L2：启动参数与子应用改造

### 4.1 WebView2 低内存启动参数

pywebview 创建窗口时可通过环境变量传 WebView2 参数。在 `launcher.py` 启动前设置：

```bash
# Linux / macOS
export WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--low-memory-mode --disable-gpu-compositing"
python launcher.py

# Windows (PowerShell)
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--low-memory-mode --disable-gpu-compositing"
python launcher.py
```

| 参数 | 效果 | 副作用 |
| --- | --- | --- |
| `--low-memory-mode` | 降 40-60 MB | 复杂页面可能卡顿 |
| `--disable-gpu-compositing` | 降 20-30 MB | 动画掉帧（已关动效则无影响） |
| `--single-process` | 降 80-120 MB | **不稳定**，子应用 iframe 崩溃会带崩主进程 |
| `--disable-features=WebView2...` | 禁用部分特性 | 按需调整 |

> `--single-process` 在多 iframe 场景（子应用页面）下风险高，仅建议单应用专用设备使用。

### 4.2 子应用改静态 HTML

每个 Python 子应用启动后多占 20-30 MB（Python 解释器 + 应用代码）。如果某应用只是展示静态内容（文档、配置说明、简单表单），可改为**纯静态 HTML 应用**——不 spawn 进程，由 launcher 的 HTTP 服务器直接托管。

**判断标准**：应用的 `app.py` 如果只是 `serve_page("index.html")` 且没有后端 API 逻辑，就适合改静态。

**改造方法**：在 `app.json` 中**删掉 `cmd` 和 `port` 字段**，launcher 会将其识别为 stub 应用，点击后直接显示占位页或由 launcher 托管静态资源。

## 5. L3：架构级优化

### 5.1 纯 HTTP 模式（无桌面窗口）

如果嵌入式设备**不需要本地窗口**（例如通过远程浏览器访问），可省掉 pywebview 的 10 MB：

```bash
export LAUNCHER_HTTP_ONLY=1
python launcher.py
```

launcher 只起 HTTP 服务，不创建桌面窗口。用其它设备的浏览器访问 `http://<设备IP>:8000/`。

> 注意：默认监听 `127.0.0.1`（仅本机），需改 `config.json` 的 `launcher.host` 为 `0.0.0.0` 才能远程访问。生产环境务必加反向代理 + 鉴权。

### 5.2 远程访问架构

把 launcher 部署在性能较强的服务器上，嵌入式设备只跑一个浏览器：

```
[嵌入式设备]  浏览器  →  网络  →  [服务器]  launcher + 子应用
```

- 嵌入式设备：只跑浏览器，内存 ~150 MB
- 服务器：跑 launcher + 所有子应用，资源不受嵌入式限制
- 缺点：依赖网络，离线不可用

## 6. 嵌入式部署检查表

部署前逐项确认：

- [ ] `config.json` 的 `ui.fx_enabled` 按需设为 `false`
- [ ] `config.json` 的 `ui.fx_particle_count` 降到 `12`-`20`
- [ ] `config.json` 的 `ui.show_window_buttons` 设为 `false`（kiosk 场景）
- [ ] 屏幕分辨率降到目标值（如 1024×600）
- [ ] 布局编辑中隐藏不常用应用，只保留 5-8 个
- [ ] 静态内容应用已去掉 `cmd`/`port` 字段
- [ ] `config.json` 无 JSON 注释（`//` 会导致解析失败）
- [ ] Python 环境已安装（`python3 --version` 确认 3.10+）
- [ ] 仓库 URL 配置为自己的镜像（HTTPS + basic auth 可选）
- [ ] 系统级应用全部预装到 `apps/system/`

## 7. 常见问题

**Q：改了 config.json 但没生效？**
A：① 确认没有 JSON 语法错误（注释、 trailing comma、缺引号）；② 浏览器硬刷新（Ctrl+Shift+R）或重启 launcher。

**Q：动效关了但还是卡？**
A：检查是否有子应用在后台跑（最近任务面板），每开一个 Python 子应用 +20-30 MB。关掉不用的应用。

**Q：RK3588 (8GB) 能跑满 26 个应用吗？**
A：能。8GB 内存下 293 MB WebView2 + 26×25 MB 子应用 ≈ 943 MB，占 12%，完全够用。瓶颈通常在 CPU（多应用同时跑时），不在内存。

**Q：512MB 内存的设备能跑吗？**
A：勉强。必须：① `fx_enabled: false` ② 只装 3-5 个应用 ③ 纯 HTTP 模式 + 远程访问。或者考虑换原生 GUI 方案（见 [02-项目架构](02-项目架构.md)）。
